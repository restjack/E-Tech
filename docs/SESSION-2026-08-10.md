## E-Tech 0.32.0 → 0.32.6

**The export filter reached exactly two factories per outlet and then stopped
forever.** `export_filter_position()` returned an unsnapped tile coordinate
while the engine places a 1x1 entity at the tile CENTRE, so the sweep's
"is it where it should be?" check was never true. The same two filters were
teleported onto themselves every pass, the per-pass budget of 2 was spent
before reaching any unfitted factory, and it never converged. Eli's save: 214
factories, 4 filters, stuck. **Every other assertion passed throughout**,
because the two it did fit were placed perfectly.

Fixed by snapping the target. Then:

- **The runtime test now builds FOUR factories** and asserts all of them get a
  filter. Verified by reintroducing the bug: `2 of 4 fitted`.
- **That check runs on its own deadline**, not behind the rule-writing gate.
  First attempt put it after the gate, and against the buggy build no filter
  ever reached the main factory, so every assertion below became unreachable
  and the run reported **INCONCLUSIVE rather than FAILED**. A stalled sweep has
  to fail loudly. Third time this pattern has bitten (see the lint-returns-0
  and matrix-passes-on-unloaded-mod notes in the previous session doc).
- **Repositioning got its own budget** (20/pass) separate from creating
  (2/pass). Creating raises build events and registers a record; a teleport of
  a collision-free entity is near free. Migrating 214 filters was taking ~3.5
  minutes of visibly half-moved factories after any version that moves the
  anchor.

**Where the filter lives, final.** Out of the room entirely, beside
Factorissimo's own interior fittings. Every tier uses the same offsets from the
interior centre, so one constant covers all of them including Mk4:

    pole                x = -4,   y = half + 2     (2x2, substation sprite)
    overlay controller  x = -3.5, y = half + 3.5
    export filter       x = -4.5, y = half + 3.5   <- one tile left of it

`INSET` is measured from the DOOR-SIDE wall and `door_y` is positive in every
tier (+16/+24/+31/+61), so the wall is BELOW and a larger inset moves it UP.
Negative inset moves it out past the wall. **Do not set inset -2** to put it
"level with the pole": the pole's collision box is `j = 0.99`, covering
`half+1 .. half+3`, and the device lands underneath the sprite, invisible.

Position assertion now checks against **Factorissimo's own layout offsets**
(beside the controller, not overlapping the pole) rather than restating
E-Tech's constants back at itself.

**Panel dead space**, three iterations to get right:

- Stock grid 8 → 16 → **12** columns. 16 was picked off an older, wider
  screenshot; only 9 fitted and it grew a horizontal scrollbar, which is worse
  than a narrow grid because nothing lines up between rows.
- Factories list is **not** horizontally stretchable — that tab's rows are what
  give the panel its width, and stretching the pane made the rows overflow it.
- Factories list vertical cap 420 → **730**, not 640: the panel is as tall as
  its tallest tab, and the stock tab carries a search box and two dropdowns
  ABOVE its 640 pane. Matching 640 left a band exactly that header's height.

## The mod pack — three folders became one

`Projects\Factorio (Patched-mods) 2.1.9\` is now the single home.

    <root>\          zips players install — ACTIVELY USED only
    A Documents\     README.txt, install-mods.bat, PATCH-NOTES.txt,
                     mod-list.json, mod-settings.dat
    Archived\        retired/superseded zips
    Archived\docs\   old manifest, audit, process doc, server-update notes

`Projects\Factorio Mod Pack\` and `Projects\factorio-mod-patches\` are **gone**
(the latter, with its git history, is at `Desktop\Trash\`). **PATCH-NOTES.txt
is the file to read** — every patch, what it changes, why, and how to re-audit
against the portal API.

**`install-mods.bat` copies `*.zip` from the folder ABOVE it and does not
recurse.** Anything in the root reaches every player and the server; anything
in `Archived\` does not. Moving the .bat into `A Documents\` silently broke it
for one revision — it reported success and copied nothing.

Also: the pack's `mod-list.json` was dated 2026-07-21, before the memory-unit
forks existed, so it enabled the ORIGINALS and had never heard of the forks.
Refreshed from the live one.

## Third-party patches made tonight

All three are in the pack root and need distributing to the server and every
client — multiplayer requires byte-identical zips.

**Large-PowerPoles 2.1.3** — the author released his OWN 2.1.2 on 2026-07-30,
after ours. Same number, different sha1: Factorio shows no update and clients
silently fail to match. Rebuilt on his tree, renumbered. Fix is two lines
(`minable` became read-only in 2.1, use `minable_flag`). Our info.json had also
been crediting Kuxynator; the author is Thedms.

**kry-inserters 5.2.4** — `func.lua:47` indexed the optional Things mod's
`mod-data` prototype with no guard. 5.2.3 shipped 2026-08-11 01:25 UTC and
broke on arrival for everyone without that mod.

**maraxsis 1.34.53** — `water-treatment.lua:116` unlocked `ske_h2o` because
Vesta is INSTALLED, but Vesta only defines that recipe when its
`ske_vesta_legacy_recipes` startup setting is on. Keyed on the setting, not on
`data.raw`: maraxsis declares no dependency on Vesta, so load order is not
guaranteed. **Built on 1.34.51, not 1.34.52** — see below.

**Krastorio2-spaced-out 2.0.16** — 18 icon layers declared `icon_size`
128/256 over 64px art. **Cause never proven**: the same error is in the logs
for 2.0.14 as a NON-FATAL warning, and those runs reached "Factorio
initialised". Recorded as unresolved in PATCH-NOTES.
